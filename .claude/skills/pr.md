# PR 작성 스킬

사용자가 "PR 작성해줘" 또는 "/pr"이라고 하면 아래 단계를 순서대로 실행합니다.

---

## 1단계 — 브랜치 및 이슈 정보 수집

```bash
git rev-parse --abbrev-ref HEAD
```

브랜치 이름에서 이슈 번호를 추출합니다.
- `feature/#111` → 이슈 번호 `111`
- `fix/#72` → 이슈 번호 `72`
- `hotfix/explore-tab` → 이슈 번호 없음

베이스 브랜치를 판단합니다.
- `feature/*` / `fix/*` → `develop`
- `hotfix/*` → `release`
- 판단 불가 시 → `develop`

브랜치 타입으로 PR TYPE을 결정합니다.
- `feature/*` → `feat`
- `fix/*` → `fix`
- `hotfix/*` → `hotfix`
- `refactor/*` → `refactor`
- `chore/*` → `chore`

---

## 2단계 — GitHub 이슈 제목 조회

이슈 번호가 있을 때만 실행합니다.

```bash
gh issue view {이슈번호} --json title --jq '.title'
```

실패하면 (이슈 없음, gh 미설치 등) 이슈 제목을 빈 값으로 둡니다.

---

## 3단계 — 변경 내용 수집

```bash
git log {베이스브랜치}..HEAD --oneline
git diff {베이스브랜치}...HEAD --stat
git diff {베이스브랜치}...HEAD
```

---

## 4단계 — PR 초안 생성

수집한 정보를 바탕으로 아래 템플릿을 **한국어**로 채웁니다.

### PR 제목 형식

```
[#{이슈번호}] {TYPE}: {이슈 제목}
```

- 이슈 제목은 `gh issue view`로 가져온 실제 GitHub 이슈 제목을 사용합니다.
- 이슈 번호가 없으면 diff 내용을 요약한 한 줄을 제목으로 사용합니다.
- 예: `[#111] feat: 탐색탭 뉴스레터 제보하기 기능 추가`

### 각 섹션 작성 기준

**📌 Summary**
- 이 PR이 무엇을 하는지 1~3문장으로 설명합니다.
- 커밋 목록 나열이 아니라 변경의 "의도"와 "영향"을 서술합니다.
- 예: "탐색탭에서 뉴스레터 제보하기 기능을 추가합니다. 사용자가 제보 버튼을 탭하면 바텀시트가 나타나고, 직군 선택 후 제출 시 API를 호출합니다."

**✍️ Description**
- 구현 방식, 구조 변경, 주요 파일을 bullet point로 서술합니다.
- `- close: #이슈번호`를 첫 줄에 포함합니다. 이슈 번호가 없으면 `- close: ` 빈칸으로 둡니다.
- TCA 패턴 변경(Reducer, Action, State, Delegate Action)이 있으면 언급합니다.

**💡 PR Point**
- diff에서 비자명한 설계 결정, 트레이드오프, 고민했던 부분을 서술합니다.
- 예: "Delegate Action을 통해 자식 Reducer가 부모에게 바텀시트 표시를 요청하도록 했습니다. 자식이 직접 부모 상태를 바꾸지 않도록 하기 위함입니다."
- 내용이 불분명하면 빈칸으로 두고 사용자에게 채워달라고 요청합니다.

**📚 Reference**
- 자동으로 파악할 수 없습니다. 주석으로 안내만 남깁니다.

**🔥 Test**
- diff를 분석해 테스트해야 할 시나리오를 체크리스트로 제안합니다.
- 예:
  - `- [ ] 제보하기 버튼 탭 시 바텀시트 노출 확인`
  - `- [ ] 직군 미선택 상태에서 제출 버튼 비활성화 확인`
  - `- [ ] API 호출 성공 시 토스트 메시지 노출 확인`
  - `- [ ] API 호출 실패 시 앱 크래시 없음 확인`

### 출력 템플릿

아래 형식 그대로 출력합니다. 주석(`<!-- -->`)은 삭제하지 않습니다.

```markdown
## 📌 Summary
<!-- PR 요약을 써주세요. -->
{요약 내용}


## ✍️ Description
<!-- PR에 대한 자세한 설명을 써주세요. -->
- close: #{이슈번호}
{설명 bullet points}

## 💡 PR Point
<!-- 코드를 작성할 때 고민했던 부분을 적어주세요 -->
{설계 결정 내용}

## 📚 Reference 
<!-- 참고할 만한 자료가 있다면 링크나 시각 자료를 달아주세요. -->
<!-- 참고한 디자인 시안, 피그마 링크 등이 있다면 직접 추가해주세요 -->


## 🔥 Test
<!-- Test -->
- [ ] {테스트 시나리오 1}
- [ ] {테스트 시나리오 2}
```

## 5단계 — 사용자 확인 및 PR 생성

초안을 출력한 뒤 다음 안내를 덧붙입니다.

---
**PR 제목:** `[#{이슈번호}] {TYPE}: {이슈 제목}`
**베이스 브랜치:** `{베이스브랜치}`

위 초안으로 PR을 생성할까요?

1. **`gh pr create`로 바로 생성** — 위 제목과 내용으로 GitHub PR을 만듭니다
2. **초안만 사용** — 위 내용을 복사해서 GitHub 웹에서 직접 작성합니다
3. **내용 수정 후 재생성** — 수정할 섹션을 알려주세요

> 📌 **Reference** 섹션은 자동으로 채울 수 없으니 디자인 시안, 피그마 링크 등을 직접 추가해주세요.
---

사용자가 **1번**을 선택하면 아래 명령을 실행합니다.

```bash
gh pr create \
  --base {베이스브랜치} \
  --title "[#{이슈번호}] {TYPE}: {이슈 제목}" \
  --body "$(cat <<'PRBODY'
{전체 PR 본문}
PRBODY
)"
```

PR URL이 반환되면 사용자에게 전달합니다.
